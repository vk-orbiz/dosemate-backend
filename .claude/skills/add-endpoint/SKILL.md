# Add an endpoint

## 1. User-owned CRUD resource (the common case): scaffold it
```bash
uv run python scripts/make_api.py <name> --fields "title:str description:str? done:bool" --dry-run
uv run python scripts/make_api.py <name> --fields "title:str description:str? done:bool" --wire
uv run ruff check . && uv run ruff format --check . && uv run mypy app && uv run pytest
```
Types: `str int bool float`, `?` = optional. `--wire` edits errors, tables, migration, protocols, deps, main, server. It refuses to overwrite; do not use `--force` without asking.
Then replace the generic logic with the real business rules (service + validators) and add tests for them. Tune DTO limits (default `max_length=255`).

## 2. Anything else (custom endpoint, non-CRUD)
Mirror `login` in the auth feature. Inside-out, one file per layer:
1. `models/` types; 2. `core/errors.py` (+ `error_map.py` if it needs its own status);
3. `service/protocols.py` port + `service/<noun>.py` logic (raise domain errors);
4. `repo/` SQL (+ `repo/entities/`); schema change -> skill `add-migration`;
5. `transport/http/`: `dto/`, `validators/`, `protocols.py` (`XSvc`), `handlers/`, `routes/` (`/v1/...`), `deps.py` dep;
6. `main.py` construct + `app.state`; `server.py` `include_router`;
7. tests: service unit test with a fake repo + one integration test per endpoint (route coverage fails the push otherwise).
Protected route: add `user_id: CurrentUserId`, pass it down, and scope every query by it (other users' rows are 404).

Rules and layer details: `agent.md` and the `CLAUDE.md` in each layer folder.
